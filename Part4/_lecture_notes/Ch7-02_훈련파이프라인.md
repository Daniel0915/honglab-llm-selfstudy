사전훈련	pre-training	언어와 세상 지식의 기반을 만든다	웹 대규모 코퍼스로 다음 토큰을 예측하도록 학습시킵니다. 연산 예산의 대부분이 여기에 들어갑니다. 학습률은 웜업(warm-up)을 지나 최고치에서 길게 유지(stable)됩니다.
중간훈련	mid-training
어닐링(annealing)이라고도 부릅니다
	베이스를 공개하기 전에 추론 · 코드 같은 능력을 심는다	같은 런의 마지막 감쇠 구간(decay)에 교과서 · 추론 트레이스(reasoning trace) · 코드처럼 비싼 데이터를 집중 배치합니다. 학습률이 낮아지며 파라미터 변화 폭이 줄어드는 구간이라, 여기서 학습한 데이터가 가장 크게 반영됩니다. 손실도, 손실이 걸리는 토큰도 사전훈련과 같습니다.

Pre-training
이어서 사전훈련
	공개된 베이스를 새 도메인 · 언어로 옮긴다	감쇠가 끝나 공개된 베이스 위에서 다시 시작합니다. 학습률이 최저값까지 내려가 있으므로 재가열했다가 다시 감쇠(re-warming · re-decay)시키고, 이때 옛 데이터를 함께 섞어 망각을 줄입니다(리플레이, replay). 논문마다 continual · continued 두 표기를 섞어 씁니다.
지시 파인튜닝	SFT
Supervised Fine-Tuning · 지도 파인튜닝
	지시를 따르는 형식을 익히게 한다	지시–응답 쌍을 정답으로 주고 그 응답을 생성하도록 학습시킵니다. 손실 형태는 그대로고 손실 마스크(loss mask)가 바뀝니다 — 사용자 차례는 빼고 응답 토큰에만 손실을 겁니다. 지도 신호가 지시–응답이라 지시 튜닝(instruction tuning)이라고도 부릅니다.
선호 정렬	preference alignment
대표 방법 DPO · Direct Preference Optimization · 직접 선호 최적화
	같은 정답 중 사람이 더 좋아하는 쪽으로 기울인다	선호쌍(preference pair · chosen / rejected)에서 바로 모델을 갱신합니다. 여기부터 목적함수 자체가 바뀝니다. 원형인 RLHF(Reinforcement Learning from Human Feedback)는 사람이 매긴 선호로 보상 모델(reward model)을 따로 학습시켜 그 보상을 올리는 방식이고, DPO는 보상 모델을 없앤 간소화판이라 구현 난도가 훨씬 낮습니다.
강화학습	reinforcement learning · RL
대표 방법 RLVR · RL with Verifiable Rewards · 검증가능 보상 강화학습
	채점되는 과제에서 정답률 자체를 끌어올린다	사람 대신 검증기(verifier)가 보상(reward)을 줍니다 — 정답 대조, 테스트 통과 여부. 조건은 「추론 과제인가」가 아니라 「코드로 채점되는가」입니다. 그래서 수학 · 코드만이 아니라 형식 준수(JSON 스키마 · 길이 · 금칙어), 툴 · 에이전트의 작업 성공 여부, 검색의 정답 도달도 전부 여기 들어갑니다. 반대로 페르소나 · 문체처럼 검증기를 코드로 짤 수 없는 것은 선호 정렬 쪽 일입니다.
증류	distillation
knowledge distillation · 지식 증류
	더 잘하는 모델의 답을 옮긴다	정답을 사람이 아니라 다른 모델이 줍니다. 주는 쪽을 교사(teacher), 받는 쪽을 학생(student)이라 부릅니다. 학생이 스스로 문장을 만들고 교사가 그 문장을 채점하는 방식(온폴리시 증류, on-policy distillation)이면 손실이 KL 발산(KL divergence)으로 바뀝니다 — 교사의 확률분포와 얼마나 다른지를 재는 값입니다. 정답 응답이 필요 없어서 프롬프트와 교사 모델만 있으면 됩니다.
기타 용어들
런 run — 훈련을 처음부터 끝까지 한 번 돌리는 것. 중간에 멈췄다 이어도 스케줄이 이어지면 같은 런입니다. 중간훈련과 CPT 사이에서 런이 한 번 끊깁니다.
학습률 learning rate · LR — 갱신 한 번에 파라미터를 얼마나 크게 바꿀지. 단계 이름의 절반은 학습률 곡선 위의 위치를 가리키는 말입니다.
어닐링 annealing — 원래는 금속·유리를 가열했다가 천천히 식히는 열처리 기법(풀림)입니다. LLM에서는 학습률을 최종값까지 빠르게 낮추는 구간을 가리키며, 중간훈련과 사실상 같은 곳을 부르는 다른 이름입니다.
재가열 · 재감쇠 re-warming · re-decay — 최저값까지 내려간 학습률을 다시 올렸다가 다시 내리는 것. CPT와 중간훈련을 가르는 동작입니다.
리플레이 replay — 새 데이터에 옛 데이터를 섞어서 훈련시키는 것. 이전에 학습한 내용을 잃는 파국적 망각(catastrophic forgetting)을 막습니다.
손실 마스킹 loss masking — 손실을 일부 토큰에만 걸고 나머지는 빼는 것.
후속 훈련 post-training — 흐름도에서 SFT부터 오른쪽 넷을 묶어 부르는 말입니다. 사후훈련 · 사후학습으로도 번역되지만 이 강의에서는 원어의 뜻을 살려 후속 훈련으로 부릅니다.
교사 · 학생 teacher · student — 증류에서 답을 주는 쪽과 받는 쪽. 교사가 반드시 더 큰 모델은 아닙니다 — 2026년 프런티어 레시피는 같은 크기의 도메인 전문가 체크포인트(checkpoint)를 교사로 씁니다(아래 MOPD 절). 규모가 아니라 전문화가 좋은 교사를 만듭니다. 교사가 공개 가중치(open weights)여야 확률분포(로짓, logits)를 꺼내 쓸 수 있습니다. 폐쇄형 API 교사는 글자만 받을 수 있습니다.
온폴리시 · 오프폴리시 on-policy · off-policy — 훈련에 쓰는 문장을 지금 훈련 중인 모델이 직접 만들었는가(온폴리시), 아니면 다른 모델이 미리 만들어 둔 것인가(오프폴리시). policy(정책)는 강화학습 용어로 「지금 훈련 중인 모델 자신」을 가리킵니다. 오프폴리시로 배우면 학생은 자기가 실제로 쓸 문장을 한 번도 못 보고 훈련을 마칩니다.
참고: 표기는 「폴리시」로 굳어 있지만, 미국식 발음은 「팔러시」에 가깝습니다.

앞의 넷은 손실 형태가 전부 같습니다(다음 토큰 예측). 그중 앞의 셋은 손실이 걸리는 토큰까지 같아서, 실제로 다른 것은 데이터와 학습률 위치뿐입니다. SFT는 손실 형태는 같고 마스킹(masking)이 다르며, 목적함수가 정말로 바뀌는 것은 DPO부터입니다 — 그 뒤 셋은 서로도 다릅니다. DPO는 쌍의 우열을, RLVR은 정답 여부를, 증류는 교사 분포와의 어긋남을 줄입니다.
내가 무엇을 준비해야 하는가로 읽으면 표가 한 줄로 정리됩니다. SFT는 지시와 응답을 둘 다, DPO는 응답 여러 개와 그 우열, RLVR은 프롬프트와 검증기, 증류는 프롬프트와 교사 모델만 있으면 됩니다. 오른쪽으로 갈수록 사람이 쓰는 글이 줄고 모델이 만드는 몫이 늘어납니다.
이 데이터들이 실제로 어떻게 생겼는지는 다음 편(지시 파인튜닝)에서 공개 데이터셋의 실물로 봅니다.
일곱 칸을 전부, 이 순서대로 밟아야 하는 것은 아닙니다. 앞의 넷은 순서가 사실상 고정입니다 — 특히 CPT를 SFT 뒤에 하면 지시를 따르는 능력이 지워집니다. CPT는 원시 텍스트에 손실을 거는 단계라 대화 형식을 되돌려 놓기 때문입니다.
반면 DPO부터는 조합도 순서도 자유입니다. DeepSeek-R1-Zero는 베이스에서 곧장 강화학습으로 직행했고(SFT도 DPO도 없이), 거꾸로 Olmo 3는 DPO를 거친 쪽이 강화학습의 더 나은 출발점이라고 실측으로 보고했습니다. DPO가 먼저 나쁜 답을 눌러 두면 강화학습 초반에 보상이 전부 0이라 통째로 버려지는 배치가 줄기 때문입니다.

훈련 진행 (토큰 수)

그래프의 값은 3B급(SmolLM3) 기준입니다. 후속 훈련 학습률은 모델이 커질수록 더 내려가고, LoRA로 일부만 갱신하면 반대로 올려 잡습니다 — 저rank 부분만 바뀌어 실제 가중치 변화 폭이 작기 때문입니다. 같은 크기라도 베이스 모델에 따라 최적값이 몇 배씩 갈리므로 학습률 탐색은 생략할 수 없습니다.
SmolLM3 전 과정 사례

HuggingFace가 SmolLM3(3B · 총 11조 토큰)를 만들며 단계마다 토큰 수를 모두 공개했습니다. 이 한 모델 안에 중간훈련과 CPT가 둘 다 들어 있습니다.

순서를 계획대로만 밟지는 않습니다. 같은 문서가 이렇게 적습니다 — 연대기적으로 중간훈련은 SFT보다 앞이지만, 이득이 있을지는 SFT를 한 번 돌려 약점을 확인한 뒤에야 드러납니다. 그래서 실무에서는 SFT로 약한 곳을 찾고 → 그 부분을 겨냥해 중간훈련하고 → 다시 SFT를 반복합니다.

증류를 조금 더

흐름도의 마지막 칸이지만, 증류는 한 칸에만 있는 것이 아닙니다. 바로 위 SmolLM3 표를 다시 보십시오 — CPT 칸에 「증류 추론 트레이스」가 들어가 있습니다. 큰 모델이 만든 추론 과정을 받아 적은 데이터로 훈련시킨 것이니 그것도 증류입니다. 즉 증류는 단계 이름이라기보다 「정답을 어디서 얻는가」에 대한 답이고, 파이프라인 여러 자리에 나타납니다.

on-policy distillation	학생이 스스로 문장을 만들고, 교사가 그 문장의 토큰마다 점수를 매긴다	공개 가중치(open weights) + 같은 토크나이저(tokenizer)
확률분포를 토큰 자리마다 맞춰야 하므로 보통 같은 계열에서 고른다 (Qwen3-32B → Qwen3-8B)
	여기서만 손실이 KL 발산으로 바뀝니다. 정답 응답이 아예 필요 없고 프롬프트와 교사만 있으면 됩니다

오프폴리시로 배우면 학생은 자기가 실제로 쓰게 될 문장을 한 번도 보지 못한 채 훈련을 마칩니다. 시험은 자기 문장으로 치는데 연습은 남의 문장으로만 한 셈입니다. 온폴리시 증류는 그 어긋남을 없앱니다 — 학생이 쓴 문장을 놓고 교사가 토큰 하나하나를 채점하므로, 강화학습처럼 자기 문장으로 배우면서도 강화학습과 달리 빽빽한 채점표를 받습니다.

왜 굳이 — 강화학습보다 싸고, 게다가 다르게 좋습니다

Qwen 팀이 같은 출발점(오프폴리시 증류를 먼저 마친 Qwen3-8B)에서 갈라 강화학습과 온폴리시 증류를 각각 돌리고 연산량까지 나란히 공개했습니다. 두 증류는 대립이 아닙니다 — 실무에서는 오프폴리시로 기초를 깔고 온폴리시로 올리는 2단으로 씁니다.

방법	GPU 시간	결과
강화학습	17,920 시간	기준
온폴리시 증류	1,800 시간	약 1/10 비용, 그런데 성능은 더 높았다

출처 — Qwen3 Technical Report (2025년 5월 · arXiv:2505.09388) Table 21. 수학 · 코드 쿼리 한정 비교. Qwen3의 작은 모델 여섯 개(0.6B–14B와 30B MoE)가 이 방식으로 만들어졌습니다.

싼 것보다 중요한 차이가 하나 더 있습니다. 같은 표에서 강화학습은 이미 풀 수 있던 문제를 더 자주 맞히게 했을 뿐, 여러 번 시도했을 때의 정답률은 전혀 올리지 못했습니다 — 못 풀던 문제는 끝내 못 푼 것입니다. 반면 증류는 그 정답률까지 올렸습니다. 강화학습은 있는 것을 다듬고, 증류는 없던 것을 넣습니다.
작은 모델일수록 증류가 답입니다. DeepSeek이 R1을 내면서 작은 모델에는 강화학습을 일부러 쓰지 않았고, 이유를 이렇게 적었습니다 — 작은 모델은 어려운 문제를 거의 못 풀기 때문에 보상이 거의 0만 돌아옵니다. 맞았다 · 틀렸다만으로는 배울 것이 없는 것입니다. 반면 큰 모델이 푼 풀이 과정을 받아 적게 하면 매 토큰이 정답이라 배울 것이 촘촘합니다. R1이 만든 80만 건(추론 60만 + 비추론 20만)으로 1.5B–70B 모델 여섯 개를 만들었습니다.
2026년 — 여러 교사를 하나로 합치는 데 씁니다

요즘 큰 모델들은 수학 · 코딩 · 에이전트처럼 분야별로 전문가 모델을 따로 키운 뒤 증류로 하나에 합칩니다. 이것을 다중 교사 온폴리시 증류(Multi-teacher On-Policy Distillation · MOPD)라고 부릅니다. 분야를 섞어서 한 번에 강화학습하면 보상끼리 간섭해 한쪽이 늘면 다른 쪽이 줄어드는 문제가 생기는데, 전문가를 따로 키우면 그 간섭을 피할 수 있습니다.

모델	공개	배치
DeepSeek-V4	2026년 4월	분야별 전문가를 키운 뒤 합치는 강화학습을 아예 생략하고 증류로만 통합
Nemotron 3 Ultra	2026년 6월	SFT → 강화학습 → 증류. 강화학습을 하고 그 위에 증류를 얹는다. 교사를 열 개 넘게 씁니다
Solar Open 2 업스테이지	2026년 7월	열두 개 분야 전문가를 만든 뒤 증류로 통합
Motif 3 모티프테크놀로지스	2026년 7월	일반 SFT → 강화학습 전문가 여섯(GRPO · 검증기 13종) + 소프트웨어 전문가 하나(SFT) → 일곱을 MOPD로 학생 하나에 통합

Motif 3의 검증기 13종이 앞서 말한 「강화학습은 수학 · 코드만이 아니다」의 실물입니다. 전문가 교사들이 맡은 분야가 에이전트 도구 사용 · 전문 업무 · 소프트웨어 공학 · 롱컨텍스트 추론과 모르면 모른다고 하기(abstention) · 수학 · 코드와 과학입니다 — 검증기를 짤 수 있으면 무엇이든 강화학습의 대상이 됩니다.

국내 두 팀이 모두 이 방식을 골랐습니다. 한국 독자 파운데이션 모델 사업에 나온 모델들의 후속 훈련 골격이 여기로 수렴했다는 뜻입니다.

다만 자리가 아직 굳지 않았습니다. 같은 해에 DeepSeek-V4는 증류로 강화학습을 대체했고, Nemotron 3 Ultra는 강화학습 뒤에 얹었습니다. 정반대 배치인데 둘 다 좋은 결과를 보고했고, 제3자 재현은 아직 없습니다. 흐름도에서 증류를 맨 끝에 둔 것은 편의상의 배치이며, 실제로는 강화학습 자리를 대신하기도 합니다.
