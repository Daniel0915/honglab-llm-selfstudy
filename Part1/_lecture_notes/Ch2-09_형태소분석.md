왜 형태소 분석이 필요한가
글자 단위의 한계
글자 단위 N-그램의 품질을 더 높이려면 단어(토큰) 단위로 전환할 필요가 있습니다. 영어는 공백으로 단어를 나누면 되지만 한국어는 교착어(agglutinative language)이기 때문에 공백만으로 나누면 학교가, 학교를, 학교는이 전부 다른 단어로 취급되어 어휘가 폭발적으로 늘어납니다.
형태소 분석기: 키위(Kiwi)
키위(Kiwi) 형태소 분석기를 사용하여 반갑습니다를 반갑 + 습니다로 분리합니다. 이처럼 의미 있는 최소 단위인 형태소(morpheme)로 분리하면 어휘 폭발 문제를 해결할 수 있습니다.
[보충] 토큰(token)이란?
앞선 강의
글자 하나가 토큰 (가, 나,   등)
이번 강의
형태소가 토큰 (반갑, 습니다, 학교 등)
언어학적 규칙으로 분리
현대 LLM
서브워드(subword) 단위의 토큰
데이터에서 통계적으로 학습
토큰 구분자 문제
공백과 토큰 구분이 겹침
토큰 사이를 공백으로 구분하면 원래 텍스트의 공백과 구분이 되지 않는 문제가 있습니다. AI에게 더 나은 방법을 요청하자 토큰을 숫자 ID로 저장하는 방식을 제안했습니다. 이것이 실제로 현대 LLM에서 사용하는 토크나이저(tokenizer)의 작동 방식입니다.
가독성을 위한 선택
토큰을 숫자 ID로 저장하면 구분자 자체가 필요 없어지므로 이 문제의 근본적인 해결책이지만 초보 단계에서는 읽기 어렵습니다. 이 강의에서는 가독성을 위해 특수 기호(<W>, <S>)를 사용하여 토큰과 공백을 구분했습니다.
전체 파이프라인
단계	도구	내용
1	파이썬	데이터 청소 (불필요한 내용 제거)
2	파이썬 + 키위	형태소 분석으로 토큰화 (빈칸도 토큰으로 포함)
3	C언어	토큰 단위 N-그램 카운팅 및 문장 생성
4	파이썬 + 키위	토큰을 역변환하여 최종 문장으로 완성
실습 결과
문체 통일의 중요성
문체가 서로 다른 책들이 섞여 있으면 부자연스러운 결과가 나왔기 때문에 동일한 장르(SF 소설)만 남기고 문체를 통일했습니다.
5-그램부터 자연스러움
이렇게 아무 기척이 나지 않을 수가 없었다처럼 자연스러운 문장이 생성되기 시작했습니다.
10-그램: 원본에 없는 자연스러운 문장
아버지가 서류에 기록을 하자, 아가씨는 전화를 걸고 얼마 후에 미소를 짓으며 안내를 하였습니다. — 원본에 없는 문장이지만 매우 자연스럽게 만들어졌습니다.
특정 단어로 시작하는 문장 생성 테스트
시작 단어 고정
앞 단어를 돈을로 고정하고 이어서 문장을 생성하는 테스트를 진행했습니다. 5-그램에서 돈을 2배로 걸고 하기로 했다라는 문장이 생성되었는데 원본에는 돈을 2배로 걸지 않겠어가 있었습니다. 걸까지는 그대로 사용하다가 그 이후를 확률적으로 다르게 이어붙여서 새로운 문장을 만들어낸 것입니다.
n이 높으면 중복 발생
n이 높아질수록 원본을 그대로 재현하는 비율이 높아지고 중복 문장도 발생합니다. 이것은 데이터가 부족하기 때문이며 데이터가 많아지면 더 다양한 문장을 생성할 수 있습니다. 이러한 현상을 과적합(overfitting)이라고 표현할 수 있습니다.
해결: 백오프(backoff)
후보가 부족할 때 n을 단계적으로 낮추며 다양성을 확보하는 전략입니다. 실제로 백오프를 적용하자 중복 문장이 사라지고 모두 다른 문장이 생성되었습니다.
예: 돈을 많이 가지고 있 다음에 올 토큰을 찾을 때
5-그램	돈을 많이 가지고 있 → ?	후보가 매우 적음!
↓	
	

4-그램	많이 가지고 있 → ?	후보 부족!
↓	
	

3-그램	가지고 있 → ?	후보 충분 ✓
[보충] 과적합(overfitting)이란?

시험 공부에 비유하면 이해하기 쉽습니다.

기출 외우기
같은 문제 → 100점
새 문제 → 0점
= 과적합 (overfitting)
원리 이해
같은 문제 → 90점
새 문제 → 85점
= 일반화 (generalization)

N-그램에서 n이 높아질수록 원본을 그대로 재현하는 비율이 높아지고 새로운 문장을 만들어내는 다양성은 줄어듭니다. 이처럼 훈련 데이터에만 지나치게 맞춰져서 새로운 데이터에 대한 성능이 떨어지는 현상을 과적합(overfitting)이라고 합니다. 이 개념은 N-그램뿐 아니라 뉴럴 네트워크를 포함한 모든 머신러닝에서 중요하게 다뤄집니다.

AI 사용 팁
여러 AI를 교차 활용
GPT에게 코드 검토를 시킨 뒤 그 결과를 클로드(Claude)에게 전달하여 코드를 개선했습니다. 서로 다른 AI의 관점을 조합하는 것도 효과적인 방법입니다.
컨텍스트의 영향
AI가 데이터 정제 코드를 C언어로 작성하려고 해서 파이썬으로 작성해달라고 지시해야 했습니다. 컨텍스트에 C 프로젝트라는 정보가 강하게 남아 있으면 AI가 모든 작업을 C로 수행하려는 경향이 있습니다.
레퍼런스 폴더 활용
교과서, 강의 대본, 참고 코드 등을 폴더에 모아두면 AI가 필요할 때 참조하여 더 안정적으로 작업할 수 있습니다. 바이브 코딩 스타일로 진행할 때와 레퍼런스를 준비해둘 때의 품질 차이가 있습니다.
에포트(effort) 설정
앞부분에서는 미디엄(medium)으로 충분했지만 작업이 복잡해질수록 부족해져서 맥스(max)로 올렸습니다.
디버깅도 AI와 함께
코드에 문제가 있는지 수정하는 과정을 여러 차례 반복했습니다. AI에게 문제를 알려주면 원인을 분석하고 수정까지 수행합니다.
전면적 재검토 요청
마지막에 전체 진행 과정을 요약하여 AI에게 전달하고 전면적으로 재검토를 시켰습니다. 진행 과정을 정리한 문서를 제공하면 AI가 전체 맥락을 파악하여 누락이나 오류를 찾아낼 수 있습니다.
파트 1 마무리
파트 1에서 한 것
클로드 섀넌(Claude Shannon)의 1948년 아이디어에서 출발하여 글자 빈도 → 바이그램 → 트라이그램 → N-그램 비교 → 문장 생성 → 형태소 분석까지 단계별로 통계적 언어 모델을 구현했습니다. N-그램은 빈도를 세는 단순한 방식이지만 n을 높이고 토큰 단위로 전환하면 꽤 자연스러운 문장을 만들어낼 수 있었습니다.
파트 2에서 할 것
이러한 한계를 극복하기 위해 뉴럴 네트워크(neural network)를 이용한 언어 모델로 넘어갑니다. 빈도를 세는 방식 대신 뉴럴 네트워크가 데이터로부터 패턴을 학습하는 방식으로 전환됩니다.
