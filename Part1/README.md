## 이 파트의 한 문장

> **「통계」란 개수를 세는 것이고, 「언어 모델」이란 그 개수로 다음 글자를 고르는 것이다.**

그리고 그 단순한 기계에서 이미 현대 LLM의 문제가 전부 나온다 —

| 파트1에서 만난 것 | 지금 어디에 있나 |
|---|---|
| 탐욕적 디코딩의 반복 문제 (`0203`) | LLM 디코딩의 temperature · `no_repeat_ngram_size` |
| BOS / EOS (`0204`) | 파트4 — 종료 토큰을 빼면 모델이 안 멈춘다 |
| n을 올리면 외워버린다 (`0206`) | 과적합 — 모든 머신러닝의 핵심 문제 |
| 조합의 대부분이 비어 있다 (`0206`) | **희소성** → 파트2 「N-gram의 저주」 |
| 토큰을 숫자 ID로 (`0208`) | 현대 토크나이저의 작동 방식 |
| 백오프 (`0208`) | Katz Backoff (1987) · Kneser–Ney (1995) |

---

## 파트2로 넘어가는 자리

파트1이 남긴 질문은 하나다 —

> **n을 올리면 외워버리고, 내리면 문맥이 부족하다. 이 트레이드오프를 어떻게 벗어나나?**

조합의 대부분이 데이터에 나타나지 않는다는 **희소성**이 근본 원인이고,
파트2는 정확히 거기서 시작한다 —
[Part2/Ch3/0301 N-gram의 저주](../Part2/Ch3/0301_NgramCurse.ipynb) →
[0303 단어 임베딩](../Part2/Ch3/0303_WordEmbedding.ipynb)이 그 희소성을 푸는 답.
